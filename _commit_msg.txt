Add SYS_CHROOT for sshd, cleanup_pending for double failures, safer Include

Audit round seven:

- P0: sshd's pre-auth privilege separation chroots into /var/empty, which
  needs CAP_SYS_CHROOT — the development profile's capability set lacked
  it, so the container sshd would very likely die before the SSH banner.
  Added precisely SYS_CHROOT on top of cap_drop=ALL.
- P0: when container cleanup ALSO failed after an activation failure,
  fail_allocation freed the GPU claims and budget while an orphan
  container might still be running. New non-terminal status
  cleanup_pending keeps every reservation; the container reference is
  recorded immediately after creation so a restarted broker can find the
  orphan; reconciliation retries the removal and only finalizes to
  failed once the container is confirmed gone. All reservation queries
  (GPU claims, CPU/memory, writable-layer budget) include the new state.
- P1: removing the managed Include directive is now gated on the managed
  file having NO remaining allocation blocks, not on which process added
  it — closing allocation A no longer strands a running allocation B's
  tunnel alias. The stale sweep clears the Include the same way.
  Tested with two allocations opened and closed in sequence.
- P1: acceptance 5.6 is unified with the handoff's hard-block standard:
  if container root can mutate host device nodes, member rollout of the
  development profile is blocked pending stronger isolation; the audit
  is detection only.
- P2: the VS Code probe now runs a tracked asyncio subprocess and kills
  plus reaps the ssh child on timeout instead of leaking it.
