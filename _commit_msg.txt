Harden VS Code shutdown, key merging, and admission-time gates

Audit round four:

- P1: on Windows the GUI killed the tunnel CLI with TerminateProcess, so
  the CLI's cleanup (managed SSH config block, listener, ssh children)
  never ran and stale blocks accumulated in ~/.ssh/config. The GUI now
  sends CTRL_BREAK_EVENT and only escalates to kill after a grace
  period; the CLI installs a SIGBREAK handler (asyncio loop signal
  handlers are unavailable on Windows) that triggers the same cleanup
  path; and the vscode command sweeps managed blocks whose local tunnel
  port is closed. Covered by a real Windows child-process test.
- P1: each tunnel connection rewrote the container's authorized_keys
  with only the connecter's keys, so an administrator opening a member's
  allocation revoked the member's key material and vice versa. The
  broker now authorizes owner plus connecter, and the container script
  merges with the existing file (dedup, newest preferred, capped at 40
  lines) instead of overwriting.
- P1: automatic queue admission re-ran only the Docker storage gate and
  trusted cached GPU/quota results, unlike direct applies which re-run
  them. Admission now re-executes the GPU permission audit and workspace
  quota gate too, so host changes between periodic audits pause queued
  admission as well.
- P0 (verification, not a code change): acceptance gains section 5.6,
  requiring a before/after host-device-node check of whether container
  root (via sudo) can chmod/chown the injected /dev/nvidia* nodes and
  affect other members, with compensating controls recorded if so.
