Make active-mode gates non-bypassable and defer features to the server

Audit round five:

- P0: the mandatory active-mode conditions (legacy audit, GPU audit,
  workspace quota, deployment approval; storage protection for the
  development profile) were only enforced when policy.mode == "active"
  in the config file, so a monitor-mode config with the gates disabled
  could be switched to active at runtime, and a persisted active mode
  survived a policy that lost its gates. The conditions now live in
  validate_active_mode_policy, enforced identically at config load,
  broker startup, and admin mode transitions.
- P1: queue admission now re-runs the GPU audit and workspace quota
  gates instead of trusting cached results (parity with direct applies).
  Broker list/status responses carry a capabilities block.
- P1: the CLI and GUI VS Code entries gate on the server's capabilities
  instead of the member's possibly stale local policy copy; the broker's
  own tunnel gate remains the enforcement point.
- P1: a non-zero exit of the local `code` launcher no longer reports
  "ready". The per-allocation SSH blocks moved into a managed
  ~/.ssh/udc-vscode-config file included from the TOP of the user
  config, so an existing `Host *` section can no longer override the
  managed User/Port options (verified with real `ssh -G`).
- P1: the development profile requires min_free_docker_gb > 0 and
  docker_storage_budget_gb > 0 in active mode, and storage_preflight
  now rejects a budget that exceeds the real Docker filesystem capacity
  plus reserve.
- P0 (verification): the handoff now records the container-root device
  node check (acceptance 5.6) as a hard precondition for opening access
  to members; audit detection alone is not isolation.
